⚠️ RLE算法的问题

核心问题识别 / Core Problem Identification

RLE压缩对于像“cdcdcdcdcd”这样的字符串效果不佳。

RLE compression isn't perfect for strings like "cdcdcdcdcd".

📉 传统方法的失效 / Traditional Method Failure

输入数据 (Input Data): "cdcdcdcdcd" (10 字符)

传统RLE处理 (Traditional RLE):

分段字符次数编码
1'c'1(1, 99)
2'd'1(1, 100)
3'c'1(1, 99)
... and so on ...

结果分析 (Result Analysis):

原始大小: 10字节
压缩后: 20字节 (1 99 1 100...)
结果: 数据增大100%！

🛠️ 标志位解决方案

标志位原理 / Flag Principle

核心思想: 使用一个标志来解决这个问题。

Core Idea: Use a flag to solve this problem.

标志值 (Flag Value): 255可以被设定为标志。

🏷️ 标志位机制 / Flag Mechanism

标志位使用原则 (Flag Usage Rules):

  1. 放置 (Placement): 255将放在每个重复值之前。
  2. 意义 (Meaning): 255表示下一个字符/组即将出现。
  3. 格式 (Structure): [255] [重复次数] [字符代码]
